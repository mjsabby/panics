## Not banned

### Growing a collection

These panic when the new capacity exceeds `isize::MAX` bytes ("capacity overflow"). A request that is merely larger than the memory available normally does not panic: it aborts the process, and no lint can prevent that, so a ban would only cover the less likely half of the problem. Where a size comes from outside, call `try_reserve` first. The optional block at the end of clippy.toml bans the functions that take a size (`with_capacity`, `reserve`, `resize`, `repeat` and others).

### More items than `usize::MAX`, or infinitely many

These need more than `usize::MAX` items, or an iterator that never ends. Two shapes get there without iterating: a range with that many items, as in `(0_u128..n).count()` or `(0..=usize::MAX).count()`, and `iter::repeat(x).count()`, which clippy's deny-by-default `infinite_iter` lint flags.
